# 个人贡献与项目限制说明

## 贡献归属

根据用户在 2026-11-17 技术学习与模拟问答中的自述，项目主体框架和代码主要由 Codex 设计、生成；用户参与需求与验收目标调整，在本机执行仿真操作，并参与日志、bag 和演示证据的核对与结论判断。本页据此说明分工；仓库归属和阶段验收分数本身不能证明某段代码由用户独立编写，也不能证明用户已独立掌握完整架构。

可用于介绍项目的表述：**“参与 Indoor Delivery AMR 的需求与验收调整，执行并核对 ROS 2/Gazebo/Nav2 两站配送的限定场景仿真验收；阅读和解释基于 ROS 2 action 的两段任务编排，以及历史代价地图残留证据。项目主体设计与代码由 Codex 协助完成。”**

项目使用现成的 Nav2 `NavfnPlanner`、`DWBLocalPlanner`，通过配置、集成和限定场景验证使用；[`navigation.yaml`](../src/delivery_robot_bringup/config/navigation.yaml)中的 `use_astar: true` 只是 Navfn 的配置。现有材料不支持“本人独立实现 A*、Navfn、DWB 或自定义规划/控制算法”。独立 Python/rclpy 编码、完整端到端架构无提示讲解、所有取消竞态排查、真机部署能力也未由项目验收分数证明。个人能力练习与项目运行验收应分别陈述。

## 已知限制

- 项目验收在 ROS 2 Humble、Gazebo Classic 的限定仿真场景完成，没有真机验收。完整场景、结果和原始证据入口见[测试报告摘要](TEST_REPORT.md)与[项目状态](PROJECT_STATUS.md)。
- V0.1 早期超时 bag 曾有约 0.15 rad 持续同向 odom 偏航；缺少足够的独立车体与轮反馈证据，来源未明。任务 action 返回不代表车体瞬时静止。
- V0.2 C6 当轮箱体移除后，全局 costmap 的高代价持续至 bag 末；[历史审计](V0.3_D4_C6_HISTORICAL_EVIDENCE_AUDIT.md)未能唯一定位来源，也不能判定更晚的消退时刻。C6 的无碰撞结果只适用于该轮证据。单次激光扫描不能证明已看见箱体全部边界。
- V0.3 是无运动、同起终点的规划恢复对照；按已记录操作没有主动清图，但缺少所有客户端清图调用的完整记录，无法排除其他客户端调用。两轮合格记录不能改写另一次证据不足的尝试，也不能证明历史 C6 问题已修复。
- 原始 bag、日志及视频主要保存在仓库外本机目录；仓库内文档与图表是索引和分析，不是原始证据的公开备份。
