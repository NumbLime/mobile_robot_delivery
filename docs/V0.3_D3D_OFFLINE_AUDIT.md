## 方法与时间边界

- 用 SQLite 只读模式核对 `PRAGMA integrity_check`、`metadata.yaml` 消息数及九个核心话题；直接反序列化 bag 中的 `/clock`、`/scan`、`/tf`、`/global_costmap/costmap` 和 `/plan`。未重录或修改数据库。Unix 接收时间只用于事件配对；窗口和消息 header 使用仿真时间，不直接相减。
- 首次删除响应分别为 `success=True`、命令退出码 0。`model_list_after_delete.log` 的响应 header 首次确认箱体不存在：D3-b **1292.049 s**、D3-c **979.744 s**。由此固定原定窗口为 **[1292.049, 1352.049] s** 和 **[979.744, 1039.744] s**。后来的 `clock_after_delete.log` 分别为 1294.9、980.8 s，只是较晚观测值，不重置窗口起点。
- `gz model -p` 实测箱体在生成后和删除前均为 world `(0.6,-1.4,0.25)`、yaw 约 0；该命令没有仿真 header。用查询前后 Unix 时间夹定机器人 world 位姿，与 bag 接收时间和近时刻 `map→odom→base_footprint` 配对，按 **`p_map = R(θ) p_world + t`** 换算。所得位置是近时刻估计，不是精确同步模型真值。两轮带箱体阶段的估计中心分别约 map `(0.505,-1.462)`、`(0.544,-1.430)`；定位随时间漂移，不把 world 数字直接当 map 坐标。
- 目标格从各轮无箱体地图 **≤10**、有箱体地图 **≥90** 的交集选取，区域为当轮估计箱体外廓及 0.55 m 周边；每张地图按自身 frame、origin 和 resolution 取格。D3-b 选出 193 格，D3-c 选出 175 格。删除前其中分别仍有 165、156 格 **≥90**。这些格集用于审计比较，精确边缘格受近时刻坐标估计限制。
- 第二轮已有的 `check_window_end_maps_offline.py` 在求出 world→map 平移后，换算函数又以 `map_x/map_y` 为基点并减去该平移；该公式不是上式。其较晚三张地图的“最大代价 47”不作为本次原窗口消退的依据。
