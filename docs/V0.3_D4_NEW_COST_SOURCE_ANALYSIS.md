## 配置和分析方法

- [navigation.launch.py](../src/delivery_robot_bringup/launch/navigation.launch.py) 默认把 `navigation.yaml` 交给 `mapping.launch.py` 的 Nav2 节点；本机 `install/` 中该 YAML 是指向 `src/` 的符号链接，`cmp` 一致。[navigation.yaml](../src/delivery_robot_bringup/config/navigation.yaml) 设全局 `map` costmap 为 `static_layer → obstacle_layer → inflation_layer`，其中静态层订阅 `/map`、障碍层订阅 `/scan` 且 `marking=true`、`clearing=true`，膨胀半径 0.55 m，更新/发布为 2/1 Hz。局部 `odom` 滚动 costmap 为 `/scan` 障碍层与 0.40 m 膨胀层，更新/发布为 8/4 Hz；两张地图的 `/scan` 障碍和射线清除最大范围分别为 2.5/3.0 m。两轮 `navigation_console.log` 均显示这些图层被实例化并订阅扫描。运行时未保存逐项参数查询，因此这里区分仓库配置与启动日志，不宣称有完整运行时参数快照。
- 使用 SQLite **只读**读取 bag，以 ROS 消息类型反序列化 `/map`、`/scan`、`/tf`、两张 costmap 和 `/plan`；各消息按自身仿真 header 时间比较。生成/删除命令的 Unix 墙钟区间只与 bag `/clock` 的**接收时间**近邻配对，得到近似仿真时刻，绝不直接用 Unix 数字与仿真秒相减。箱体 world 位姿来自 Gazebo 只读查询；用近时刻 `map→odom→base_footprint` 和机器人 world 位姿估计 world→map，再按每张地图的 origin、resolution、frame 取格。Gazebo 查询无仿真 header，空间边缘格与精确事件瞬间仍有对齐误差。
- 全局目标格沿 D2 方法选取：箱体外廓及 0.55 m 周边内，基线 `≤10`、有箱体 `≥90` 的格。D3-c 为 **175 格**（近时刻 map 中心约 `(0.544,-1.430)`），D5 为 **179 格**（`box_alignment.json` 的中心约 `(0.350,-1.519)`）。本分析另用扫描朝箱体的 `[-1.25,-0.75] rad` 扇区最小量程和局部地图中箱体估计位置附近半径 0.40 m 的可见格，追踪事件先后；这两个分析区域**不替换 D2 的验收阈值或目标格**。局部格由近时刻 `map→odom` 变换换算；D5 箱体中心处于局部滚动窗口边缘之外，只比较窗口实际覆盖的 88 格。

## 箱体出现：标记来源

| 原始数据 | D3-c | D5 |
| --- | --- | --- |
| 生成请求墙钟对齐到 `/clock` 的近似区间 | 351.1–352.8 s | 1914.0–1915.0 s |
| 生成前扫描扇区最小量程 → 首次箱体近距回波 | 约 3.123 m → **352.696 s，1.310 m** | 约 3.116 m → **1914.911 s，1.365 m** |
| 局部地图可见分析格：生成前高代价格 → 首次高代价 | 0/111 → **352.8 s，108/111 格 ≥90** | 0/88 → **1915.1 s，88/88 格 ≥90** |

| 记录到的静态 `/map` 与后续带箱体全局图 | `/map` 仅 1 张；175 个目标格均为 0，带箱体全局图 175 格升至 ≥90 | `/map` 仅 1 张；179 个目标格均为 0，带箱体全局图 179 格升至 ≥90 |

生成服务首次响应为成功、模型列表随后含箱体，Gazebo 只读位姿与固定 world 输入相符；以上短距扫描回波和局部/全局高代价在箱体出现后相继出现。局部 costmap **没有静态层**，其箱体区域高代价与 `/scan` 的变化相符；全局目标格在记录到的静态 `/map` 中为 0，却在合成全局图中升高。结合实际加载的图层顺序，最有依据的来源解释是 `/scan` 障碍层标记箱体占据格、膨胀层影响周边格。单张静态 `/map` 不能证明运行全程从未收到其他地图更新；bag 也没有各图层单独输出，故不能逐格断言 99/100 的每一点分别来自障碍层还是膨胀层。

固定起终点规划也与标记一致：D3-c 有箱体路径相对基线在 `x=0.6 m` 截面向南约 0.744–0.782 m、长度增加约 0.639–0.723 m（见 [D3-d 审计](V0.3_D3D_OFFLINE_AUDIT.md)）；D5 向南 0.7522 m、长度增加 0.9896 m（见 [D5 验收](V0.3_D5_OFFLINE_ACCEPTANCE.md)）。路径改变是同期对照佐证，不能单独证明图层内部归因。

## 首次删除：扫描、局部及全局代价消退

| 原始数据 | D3-c | D5 |
| --- | --- | --- |
| 删除请求墙钟对齐到 `/clock` 的近似区间 | 976.3–978.3 s | 2449.2–2453.1 s |
| 扫描扇区最后近距回波 → 首次远距回波 | 978.102 s，约 1.352 m → **978.202 s，约 3.215 m** | 2452.916 s，约 1.380 m → **2453.016 s，约 3.104 m** |
| 局部地图可见分析格：最后高代价 → 首次全清 | 978.1 s 为 99/111 格 ≥90 → **978.5 s 为 0/111** | 2452.9 s 为 88/88 格 ≥90 → **2453.2 s 为 0/88** |
| 全局目标格：最后高代价 → 首次全清 | 977.1 s 有 156/175 格 ≥90 → **978.6 s 全 175 格 ≤10** | 2452.9 s 有 179/179 格 ≥90 → **2454.4 s 全 179 格 ≤10** |
| 首次模型列表确认箱体不存在（窗口起点） | 979.744 s | 2460.978 s |

两轮均是首次删除响应 `success=True`，随后模型列表缺席；全局与局部地图在**首次缺席确认之前**已发布低代价。因此上表的首次低代价时刻是离散发布消息给出的上界，不能把后来的模型列表时间当作代价刚消退的时刻。D3-c 的扫描清除、局部清除、全局清除先后约为 978.202、978.5、978.6 s；D5 约为 2453.016、2453.2、2454.4 s。D5 固定规划在 2452.2 s 仍绕行，2454.2 s 已与基线几何相同；这与地图消退时间相邻，但规划结果略早于下一张**发布**的全局低代价图，不能据此精确推算内部 costmap 更新时刻。

此时序与 `/scan` 障碍层的 `clearing=true` 射线清除、随后重新膨胀相容；扫描量程回升说明箱体回波已消失。**它不是清除服务未被其他客户端调用的证明。**目录中没有操作者主动清图请求/响应，D5 原窗口末不满足主动分支残留门槛；本机没有覆盖所有服务客户端调用的事件记录。也没有单独的障碍层/膨胀层栅格、逐次 `raytrace` 日志或完整运行时参数快照，因此无法把一次代价下降唯一归因于射线清除、清图服务、图层重置中的某个内部动作。不能称“已排除清图影响”。

## 结论和本项计分

两次新实验提供了同方向的独立观察：记录的静态 `/map` 目标格为空，箱体出现后近距扫描与两张 costmap 的局部高代价同步出现，首次删除后扫描和两张 costmap 依次恢复；全局目标格在两次原定窗口内均消退。结合已核实配置与启动日志，`/scan` 障碍层标记/清除及膨胀层影响是**最符合证据的机制解释**，但各图层的逐格贡献和清图服务的全部调用方仍不可直接观测。D3-b 原窗口规划密度不足的限制按既有审计保留，不把它改写为恢复成功；本报告也不把新实验的正常消退称为历史 C6 已修复。
